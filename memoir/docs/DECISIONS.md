# Decisions log

| # | Decision | Why |
|---|---|---|
| 1 | Frontend first (Phase 1), backend engine (Phase 2) only after explicit approval | Per the product spec workflow |
| 2 | React + TypeScript + Vite SPA, Tailwind, Zustand, TanStack Virtual | Review workspace and a huge virtualized grid share a lot of state; no SSR needed for a local-first tool |
| 3 | Tiered in-memory previews behind a `PreviewProvider` interface | Browsers cannot render HEIC, RAW or MKV; the interface lets Phase 2 swap in native thumbnails |
| 4 | The local engine, not the browser, does the lossless writes (embedded tags, file timestamps) | Browsers cannot set creation time, cannot reliably set modified time, and cannot rewrite EXIF or QuickTime tags losslessly |
| 5 | Duplicate removal is non-destructive by default (exclude from export); quarantine and delete are opt-in; UI always shows the folder a file is removed from | A wrongly deleted photo cannot be recovered; keeps sources read-only |
| 6 | Exact duplicates (size, partial hash, full hash) can be bulk-selected; similar (perceptual hash) never auto-selected | Avoid removing different photos that merely look alike |
| 7 | Design for 200+ GB Takeout across many ZIP parts: never extract first, index ZIP directories first, match sidecars across all parts, resumable stages | Extraction would need another 200+ GB; sidecars can sit in a different part than their photo |
| 8 | ZIP parts may be on the laptop or an external SSD; offline drives pause jobs; export preflight checks free space, filesystem (FAT32 warning) and same-drive contention; optional second export target | Real-world setups; FAT32 limits files to 4 GB and has coarse timestamps |
| 9 | Hash source bytes at ingest, before Memoir writes any metadata | Writing metadata changes the file bytes and would break later duplicate matching |
| 10 | Visual direction: Luxury + motion (page 4 of the design canvas) | Chosen after comparing Neumorphism, Luxury minimal and a Hermes-Agent-inspired style |
| 11 | Real nature photography to be supplied by the owner (own or free-license); inline SVG landscapes are placeholders | Published pages cannot load outside images; licensing |
| 12 | Timezone-only differences (EXIF local vs Takeout UTC) are `tz_only`, low priority | The most common false conflict |

## Build outcomes (implementation)

| Decision | Result |
|---|---|
| Backend engine (Phase 2) | Built in Python (FastAPI, SQLite, ExifTool, Pillow) and served together with the interface on `127.0.0.1:8787` |
| Previews | Generated by the engine (Pillow and pillow-heif for images, embedded previews via ExifTool for RAW, ffmpeg for video), not by browser WASM: simpler and faster for huge libraries |
| Job progress | Polled every second instead of server-sent events (simpler, equally responsive) |
| Choosing files | Server-side folder picker (browsers do not expose file paths); drag and drop was dropped |
| Delete from source | Not implemented on purpose; quarantine for loose files, exclude-from-export for ZIP entries |
| Interface styling | Luxury + motion, plain CSS (no Tailwind), fonts bundled so the app works offline |
| Security | Host and Origin guard so only the local Memoir page can use the API |
| ZIP staging | Each ZIP entry is staged briefly (one file at a time) so ExifTool can read it; nothing is extracted ahead of time |
